# 全链仿真 UI 使用手册

[返回首页](../README.md) ·[技术说明文档](technical-guide.md) · [快速开始](../docs/quickstart.md) · [训练到仿真](../docs/training-to-simulation.md) · [技术架构](../docs/architecture.md)

面向 Ubuntu 22.04 / Linux x86_64，需 X11 或 XWayland 图形桌面。程序已包含 Python 和 PyQt5，无需编译。
默认采用原仓库灵龙 **26 轴模型**（双腿 12＋双臂 14，头腰不参与仿真），RL 使用内置 `policy.onnx`。
请完整保留 `loong_gui_sim/`，其中的 `runtime/` 和 `native/` 是必需资源。

## 1. 安装与启动

首次使用按 [快速入门第 1、2 节](../docs/quickstart.md) 安装系统依赖、下载 LFS 文件并完成完整性检查。该页面是 GUI 系统依赖的统一安装入口。

进入整合包根目录运行：

```bash
cd OpenLoongOS-LTS
./start_sim.sh
```

GUI 自动打开仿真。点击 **“一键启动控制链”**，按提示输入本机 sudo 密码，等待 driver、interface、locomotion 启动完成。

## 2. 界面区域

![全链仿真 UI 界面与曲线示例](../docs/media/ui-preview.png)

该截图来自项目演示视频，用于识别区域；数值、进程号和输入框示例不作为当前配置。

| 区域 | 内容与用途 |
| --- | --- |
| 顶部工具栏 | 打开日志回放、一键启动控制链、停止本次进程，以及运行状态 |
| 左上 MuJoCo 画面 | 观察姿态、地面接触、辅助力；点击画面后使用 F / G / H |
| 左下「行走控制」 | EN、RC、RL 等模式切换，以及速度指令与读数 |
| 右侧 DRIVER / INTERFACE / LOCOMOTION | 查看各进程输出，定位启动和运行错误 |
| 右侧 PLOT | 选择关节、查看目标 TGT 和实际 ACT 的实时曲线 |

顶部 `SIM LIVE` 表示仿真进程在线；演示界面的 `CHAIN 3/3` 表示三个控制进程在线。进程在线不等同于已进入 RL，仍需查看当前模式与输出。

## 3. 恢复、行走与停止

1. 保持默认辅助力开启，速度指令保持为零。
2. 在“行走控制”页点击 **EN → RC**，等待恢复完成、进入 IDLE。
3. 点击 **RL**，待姿态稳定后，点击仿真画面并按 **F** 关闭辅助力。
4. 点击控制区，用一次 W 或 Q 检查前进或转向指令及响应，再按空格清零。先分别测试，再组合操作。
5. 结束时先在控制区按空格清零，再点击 **“停止本次进程”**，查看退出日志后关闭界面。

**不要在 RC / IDLE 阶段提前关闭辅助力：它们只恢复、保持关节姿态，不提供主动平衡。**
RL 自动加载唯一策略，无需额外发送模型选择键值 41。

EN 是使能，RC 是恢复，RL 是策略控制。IDLE 不代表策略正在保持动态平衡；DIS、DAMP 也不是速度指令的清零按钮。首次使用按上述顺序完成，不需要手动输入其他插件或模型键值。

## 4. 常用操作

| 操作 | 功能 |
| --- | --- |
| 控制区 W / S | 增减前后速度 |
| 控制区 A / D | 增减左右速度 |
| 控制区 Q / E | 增减转向速度 |
| 控制区空格 | 清零全部速度指令 |
| 仿真画面 F | 开关辅助力 |
| 仿真画面 G / H | 降低 / 升高辅助高度 |
| “镜头跟随” | 跟随机器人 |
| PLOT / “打开日志回放” | 查看实时曲线 / 导入 driver 文本日志 |

速度按键会累加指令，松开按键不会自动清零；S 是减小 VX，空格才是三个速度指令清零。F 是辅助力切换键，按后应确认当前状态。键盘无响应时，点击对应区域，或使用控制区同名按钮。
回放期间暂停实时控制发送。插件键值为：`rc=2`、`rl=4`、`jntTest=31`。

## 5. 查看实时曲线

以左膝目标与实际位置为例：

1. 启动控制链后选择右侧 PLOT 页。
2. 在量纲下拉框选择「位置 · rad」，勾选目标 TGT 和实际 ACT。
3. 展开「左腿」，选择 `knee`，观察两条曲线是否随时间更新。
4. 调整「最近」显示时长；需要同时看其他量时，使用水平或竖直分割创建曲线窗口，再分别选关节。
5. 「暂停显示」用于观察当前曲线，「清空数据」清理当前显示缓存；这些操作不等于停止机器人控制。

先确认数据持续更新，再比较目标与实际的趋势、时延和误差。目标与实际不重合可能来自 PD、限幅、负载或动态过程，不能仅凭一张曲线图认定某个模块故障。

没有数据时先看 DRIVER 输出，并检查 `runtime/config/driver.ini` 中的 `log2udpFlag=1`、`log2udpIp=127.0.0.1`、`log2udpPort=9870`。确认修改后的配置已通过重启生效。

## 6. 记录与回放日志

本阶段不附带旧运行日志。使用自己本次仿真的日志完成以下流程：

1. 按第 3 节完成一次短仿真操作，然后清零速度并停止控制进程。
2. 到 `loong_gui_sim/runtime/log/` 查找本次生成的 driver 文本日志，依据文件修改时间和内容确认；不同构建的文件名可能不同。`runtime_logs/` 是进程启动与运行输出，不能直接当作关节轨迹日志。
3. 在 GUI 顶部点击「打开日志回放」，选择对应的 driver 日志。
4. 按回放窗口显示的播放、暂停和时间定位控件查看姿态变化，核对开始姿态、左右关节和运动方向是否合理。
5. 结束回放后关闭回放界面；再次进行实时控制前，确认当前处于仿真运行模式并重新检查进程与速度状态。

当前 `runtime/config/replay_log.ini` 设置 `untaggedPoseSpace=joint`，即没有位姿标签的本版本日志按关节角处理。历史实机的电机角日志需要匹配模型和转换配置，不能直接按关节角套用。回放中的姿态重建也不等于重新执行原时刻的物理控制。

如果未生成可用 driver 日志，先查看 DRIVER 页输出及日志配置，保留诊断信息；不要把任意 CSV 改成 TXT 作为回放文件。

## 7. 配置与模型

以下路径相对于 `loong_gui_sim/`：

| 文件 / 目录 | 用途 |
| --- | --- |
| `runtime/model/scene.xml` | 场景入口，引用 `linglong/linglong_26dof.xml` |
| `runtime/config/driver.ini`、`driver_mujoco.ini` | 关节映射、固定 PD 与辅助力 |
| `runtime/config/plan_rl.ini` | RL 观测、动作映射及推理周期 |
| `runtime/model/onnx/policy.onnx` | 当前策略，与整合包 `models/policy.onnx` 一致 |
| `runtime/log/`、`runtime_logs/` | SDK 日志、各进程启动与运行输出 |

当前配置为 `drvNums=31`、`activeDrvNumUser=26`、`pdMode=3`、`useJntMotMap=0`、`simAnkleMap=none`；所有有效轴使用 MuJoCo 固定 PD。
更换模型时，两份 driver 的关节映射必须一致；更换策略须匹配当前 `obs[1,700] → actions[1,20]` 接口及观测定义。
修改模型、驱动或策略配置后，**退出旧 GUI 和控制链，再重新启动**。

具体训练、导出、元数据检查、策略替换和回退命令见 [训练到仿真教程](../docs/training-to-simulation.md)。替换后原发布哈希检查会报告差异；保留自己的实验备份和模型哈希。

## 8. 常见问题

| 现象 | 检查顺序 |
| --- | --- |
| `GLIBC_2.35 not found` | 确认使用 Ubuntu 22.04 对应运行环境；安装 PyQt 或更换 Python 不能解决此项 |
| 文件很小、无法执行，或出现 LFS 指针 | 执行 `git lfs pull`，再运行根目录完整性检查 |
| `Permission denied` | 检查可执行位、所在文件系统是否为 noexec；优先通过 Git 完整检出保留文件权限 |
| Qt 平台插件或窗口加载失败 | 确认当前是图形桌面终端，再按快速入门安装完整系统依赖 |
| 控制链启动失败 | 查看对应进程页输出和 `runtime_logs/`，确认 sudo 授权、端口占用及配置 CPU 号是否适合本机 |
| 恢复后倒地 | 确认已经进入 RL、辅助力状态、是否残留速度指令，以及模型是否被替换 |
| 按键无响应 | 点击对应的控制区或仿真画面；先确认速度读数是否变化，区分焦点问题和策略响应 |
| 曲线不更新 | 检查 DRIVER、UDP 日志配置和 PLOT 是否暂停 |
| 回放姿态异常 | 检查日志是否为 driver 轨迹、模型与关节顺序是否匹配、位姿空间是否为 joint |
| 退出时报 SDK 错误 | 保存完整退出日志；输入包曾记录 `Quill::remove_logger` 析构问题，见验证记录 |

需要进一步诊断时，在仓库 Issue 附上系统版本、GPU / 驱动、提交号、复现步骤、出错页日志、策略哈希和是否修改配置。

## 9. 离线自检与验证范围

在整合包根目录执行离线自检，不启动控制链：

```bash
QT_QPA_PLATFORM=offscreen ./start_sim.sh --self-test
```

输入包历史记录包含 RL 零速度、无辅助力的 30 秒进程内站立检查；本次发布验证包括依赖检查与 GUI 离线自检。完整多进程运行、窗口嵌入、镜头跟随和各速度下持续行走不能由离线自检推断，具体实测范围见 [验证记录](../VALIDATION.md)。本手册给出操作流程，不把待执行的操作描述为本次新增实测结果。
