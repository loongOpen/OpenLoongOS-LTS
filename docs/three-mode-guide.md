# 三功能全链仿真

行走、跳舞、视觉越障共用一个灵龙 26 轴机器人、一个 MuJoCo 场景，以及同一套 driver → interface → locomotion 控制链。GUI 沿用全链仿真的操作布局。切换功能时，locomotion 调度不同 plan，不退出仿真、不更换机器人、不重置世界状态。

## 启动与操作

在 Ubuntu 22.04 / x86_64 图形桌面中运行项目根目录的 `./start_openloong_gui.sh`。系统图形依赖见 [快速入门](quickstart.md)。三个 SDK 插件随包提供，不需要安装 Python 策略运行环境。

1. 点击「一键启动控制链」，在本机授权窗口输入 sudo 密码。
2. 保持辅助力开启、速度为零，点击 EN → RC，等待恢复完成。
3. 点击 RL，姿态稳定后在仿真画面按 F 关闭辅助力。
4. 在左下「插件 / 模型键值」输入数值，点击「发送键值」。

| 功能 | 键值 | SDK 插件 |
| --- | --- | --- |
| 行走 | 4 | `libplan_walking_sdk_x64.so` |
| 跳舞 | 28 | `libplan_dance_sdk_x64.so` |
| 视觉越障 | 43 | `libplan_parkour_sdk_x64.so` |
| 恢复 | 2 | `libplan_recover_x64.so` |

行走和越障沿用 W/S、A/D、Q/E 速度控制，空格清零。跳舞执行随包动作。切换前先清零速度并观察姿态；再次进入跳舞会从参考动作起点开始。辅助力、鼠标视角、镜头跟随、PLOT 和日志回放仍使用原来的控件。

场景包含一个 20 cm 箱体，中心位于世界坐标 `(4.5, 0, 0.1)`，半尺寸为 `(0.4, 0.75, 0.1)`。使用越障键值 43 后，可从起点沿 X 正向以 VX=0.6 前进测试。其他高度、连续楼梯以及实机部署需要分别验证。

## 控制与视觉数据

- `runtime/config/loco_plugins.ini` 保存键值和 SDK 插件映射。
- 关节总线为 31 槽位，26 轴有效；所有功能使用同一关节映射。
- `driver.ini` 使用 `pdMode=1`，在驱动层计算关节 PD；每个 plan 提供对应的增益。`driver_mujoco.ini` 的固定 PD 为零，避免重复施加 PD。
- 统一机器人模型使用固定的一套惯量、摩擦和求解器参数；这些物理参数不随功能切换。
- `native/libsim_depth_bridge.so` 扩展原 SDK 仿真器，从正在运行的同一场景进行射线测距。深度按训练部署约定裁剪、滤波、归一化，经 `runtime/run/depth.bin` 传给越障插件。深度缺失或过期时插件停止输出策略命令。
- 行走使用 700 维观测，跳舞使用 1610 维观测，越障使用 450 维观测及 `[1,8,18,32]` 深度历史。推理周期均为 20 ms。

运行时不需要另开 Python 仿真进程。训练目录和 `runtime/python/` 中保留的独立测试程序用于各算法的训练与部署调试。

## 构建与验证范围

SDK 适配器、行走推理及同场景深度扩展的源码位于 `loong_gui_sim/native/sdk/`。重新构建需要 Ubuntu 22.04、C++17 编译器及 Eigen 3.4 开发头文件；运行 `bash loong_gui_sim/native/build_sdk_plans.sh`。所需 SDK / MuJoCo / ONNX Runtime 接口头文件及许可保留在 `native/vendor/`。

已在 Ubuntu 22.04 上通过实际 GUI、SIM、driver、interface、locomotion 完成三功能连续切换、完整跳舞后切回行走、20 cm 箱体越障后切回行走。上述验证属于仿真测试，不代表全部地形或实机能力。


## 深度可视化

右侧 **VISION** 页显示当前仿真场景提供给越障策略的深度图，随 SIM 自动更新。
预览为裁剪、滤波后的当前帧（32 × 18），采用近黑远白灰度，显示范围 0–2.5 m；
超出量程或无回波显示为白色。状态行显示采样频率、帧龄、仿真时间和深度范围。
停止更新时清除旧图并提示状态；日志回放期间暂停实时深度预览。
预览只读取现有深度数据，不改变相机参数、策略输入或键值 4 / 28 / 43。

## 脚踝机构

三个模式共用物理闭链脚踝和真实解算库。电机反馈、回放和参数说明见 [闭链脚踝说明](closed-chain-ankle.md)。
