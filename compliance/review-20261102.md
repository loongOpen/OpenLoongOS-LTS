## 1. 对输入报告的修正

原报告保留不改，以下复核避免把“删掉许可证文字”等同于解决许可问题。

| 输入报告判断 | 本次复核 |
|---|---|
| PyQt5 确实内置 | 成立。解析原 PyInstaller CArchive 与 PYZ，确认 Qt 绑定和动态库；原始清单保留在 `previous-gui-inventory.json` |
| “只有 PyQt5 一个真风险，其余全是误报” | 证据不足。Qt 的对应库源码、替换与安装机制、版权和许可告知也需实际落实；不能只看到 `.so` 就判定义务完成 |

| “二进制搜不到 GPL 文本，所以没有随附许可” | 仓库另有许可证文件。是否随附应检查整个实际交付物，而非只在压缩后的 ELF 内搜索明文 |

| “Paramiko / Readline 字符串没有命中即不存在” | 用归档模块目录、外部扩展和文件清单补强证据；本次包内未发现这些模块，不外推为所有历史版本都没有 |
| “购买商业许可后删除 GPL 文本即可” | 不是自动处理历史分发的方案。本次按维护者选择迁移 PySide，不采购；历史分发另行确认 |

## 2. 已完成的候选包修改

- GUI 改用 PySide6 / Shiboken6 / Qt 6.11.3。修复 Qt6 模块路径、信号转发、与 QWidget.metric 同名的控件属性、分屏对象保留等适配问题。
- 改用 `onedir` 打包。第三方 Python 入口与共享库放在 `_internal/`，可替换；自有应用模块保持预编译形式。应用没有添加库哈希启动门禁。
- 加入界面“许可证”入口、根目录 NOTICE、分组件许可索引、实际库文件清单和替换说明。
- 随包提供四份精确版本官方库源码归档，总计约 70 MiB，保留构建文件和许可声明，记录 URL、SHA-256 并通过 Git LFS 管理。
- 保留完整 CPython、ICU、PyInstaller 例外、Qt 源码内含组件声明；补充 SDK 所用 ONNX Runtime 1.21.0 的 LICENSE / ThirdPartyNotices。
- 原 `licenses/loong_gui_ctrl/` 中不再对应新包的材料移出当前候选树。原发布提交和本地备份仍保留旧材料；没有为规避扫描而删除现用组件的 GPL / LGPL 正文。
- 训练代码、控制算法、ONNX 策略、机器人模型和 native / SDK 运行文件没有因迁移而修改。GUI 源来自用户提供的 `loong_gui_sim.zip`，比原二进制提交早；已恢复当前发布的 26 轴路径、关节及日志适配，不声称它就是旧二进制的精确源码。

## 4. 发布前仍需明确的事项

1. **自有 GUI 的分发许可。** 输入包没有覆盖 GUI 自有部分的独立 LICENSE；SDK 的 MIT 与训练框架的 Apache-2.0 不能自动扩展到 GUI。可由权利人确认自有 GUI 是否采用 MIT，或提供公司二进制分发条款。MIT 允许二进制分发，并不因选择 MIT 而要求同时提供应用源码；第三方 LGPL 义务仍需保留。当前没有擅自添加该授权。
2. **历史 PyQt5 分发。** 新包迁移不追溯消除旧 Git 提交、LFS 对象、下载包和已有接收者的情况。需由权利人确定历史版本的授权依据和处理方式；没有执行删库、强推或历史重写。
3. **平台复扫与组织确认。** 将最终包和清单提交原扫描平台，按文件路径解释 LGPL、Bootloader Exception 和复合版权文本。组织开源审批、贡献者同意等不能由本次二进制检查代签，也不能保证扫描“零告警”。

因此，当前准确状态是：**技术迁移及所列第三方交付材料已准备，GUI 自有许可和历史分发事项待确认；不是无条件发布批准。**
